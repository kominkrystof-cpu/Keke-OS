Issue Description
Title: Mouse input unresponsive due to missing psmouse kernel module / /dev/input/mice device

Problem
The mouse cursor does not respond to input when launching the GUI framework in Keke OS.

Root Cause
Missing PS/2 Mouse Driver: During the boot sequence, the init system logs a warning:
[WARNING] Failed to load psmouse.ko - mouse may not work

Missing Input Device Nodes: Because psmouse.ko failed to load (or is omitted from the initramfs), the kernel does not initialize the PS/2 emulation driver in QEMU, preventing the creation of device nodes such as /dev/input/mice or /dev/input/event*.

Userspace Input Failure: The C++ GUI framework cannot open the input device stream (or falls back to drawing a static cursor), leaving mouse interactions unhandled.

Solution / Workaround
Kernel Configuration: Ensure CONFIG_MOUSE_PS2=y is built statically into the kernel (bzImage) instead of compiled as a module (=m).

Initramfs Inclusion: If built as a module, include psmouse.ko inside /lib/modules/ within keke-initramfs.cpio.gz and ensure devtmpfs automatically populates /dev/input/.

QEMU Parameter: Ensure QEMU is supplied with standard PS/2 mouse or USB tablet device emulation (e.g., -device usb-tablet).
